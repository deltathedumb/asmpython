asmpython

Compile Python source to native x86-64 executables — no VM, no interpreter, no runtime dependencies.

platformWindows · Linux
python3.11+
licenseMIT

asmpython is a single-pass ahead-of-time compiler. It reads idiomatic Python, runs it through a lex → parse → sema → codegen pipeline, emits NASM assembly, and hands it to nasm and gcc to produce a standalone native binary with zero Python runtime overhead.

Four output targets are supported:

  • Windows (PE64) — .exe linked against msvcrt
  • Linux (ELF64) — ELF binary linked against libc
  • Freestanding (Multiboot1) — bare-metal kernel that boots in QEMU; no OS needed
  • Freestanding 16-bit — raw BIOS-bootable disk image (16-bit boot sector → 64-bit long mode)

Tuples & unpacking

python
a, b = 1, 2          # unpack assignment
a, b = b, a          # swap
for i, x in enumerate(xs): print(i, x)
for a, b in zip(xs, ys): print(a, b)
first, *rest = xs    # starred unpack: rest = xs[1:]
*init, last  = xs

Tuple-assignment targets may be plain names, subscripts, or attributes. A single starred target (*rest, PEP 3132) collects leftover elements into a new list. RHS is fully evaluated before any LHS store, so swaps work without a temporary.

Pattern matching #

python
# Literal patterns
match status:
    case 200: print("ok")
    case 404: print("not found")
    case _:   print("other")

# Or-patterns, capture, guard
match cmd:
    case "quit" | "exit": print("bye")
    case x if x.startswith("--"): print("flag")
    case s: print("cmd:", s)

# Sequence patterns
match lst:
    case []: print("empty")
    case [x]: print("one:", x)
    case [first, *rest]: print("head:", first)

# Class patterns with __match_args__
class Point:
    __match_args__ = ("x", "y")
    def __init__(self, x: int, y: int): ...

match shape:
    case Point(x=0, y=0): print("origin")
    case Point(px, py): print("point at", px, py)

Supported patterns: Literal, Capture (case x:), Wildcard (case _:), Or-pattern (case p1 | p2:), Sequence (case [p0, p1]:), Class (case Cls(kw=p):), As-pattern (case p as name:). Guards: case p if expr:. Mapping patterns (case {"key": v}:) are not supported.

match is a soft keyword — bare uses like match = 5, match(x), match.foo remain valid identifiers. The compiler rewrites each match to an if/elif/else chain, so pattern matching has zero runtime overhead.

Functions #

python
def greet(name: str, times: int = 1) -> str:
    return (name + " ") * times

def variadic(*args):
    for a in args:
        print(a)

# First-class functions
f = greet
print(f("hi", 3))

# Decorators
@staticmethod
def utility() -> int: ...

# *expr unpack at call site (when shape is statically known)
t = (1, 2, 3)
my_func(*t)

Default arguments (int, str, float, True, False, None literals). *args variadic. Type annotations parsed but not enforced at runtime. Recursion at any depth.

Parameters without annotations infer type from call-site arguments (string/float/list/dict/tuple literals, f-strings, constructor calls). A parameter inferred this way requires all call sites to agree on one type; ambiguous cases fall back to int.

*expr argument unpacking is supported when expr is a statically-known tuple — a name, subscript, or attribute bound to a tuple literal. Unpacking a Call result directly (f(*g())) requires assigning first.

Classes #

python
class Shape:
    def __init__(self, name):
        self.name = name

    def area(self) -> int:
        return 0

class Square(Shape):
    def __init__(self, side):
        super().__init__("square")
        self.side = side

    def area(self) -> int:
        return self.side * self.side

    def __str__(self) -> str:
        return f"Square({self.side})"

sq = Square(5)
print(sq.area())           # 25
print(isinstance(sq, Shape))  # 1

Imports & modules #

python
import math
from os import path
from . import utils           # relative import
from .utils import helper

asmpython supports two kinds of imports:

  • Bundled source stdlib — modules like re, json, csv, collections, etc. are compiled whole-program alongside your code. All their top-level definitions become globally visible.
  • FFI stdlib — lower-level modules like math, os, time, sys use direct C runtime bindings.

User modules are also whole-program compiled: import utils finds utils.py in the same directory and merges it into the compilation unit.

Inline assembly #

python
from asmpython import asm

def fast_add(a: int, b: int) -> int:
    with asm():
        mov  rax, [rbp-8]   # a
        add  rax, [rbp-16]  # + b
    return 0  # rax is the actual return

# Named operands
def cpuid_vendor() -> str:
    with asm("eax"=0):
        cpuid
        mov [rbp-8], rbx
        mov [rbp-16], rdx
        mov [rbp-24], rcx
    return ""

Inline assembly blocks are passed verbatim to NASM. The with asm(): form wraps a block; individual asm("instruction") calls insert single lines. Named operands (asm(eax=0)) emit mov setup code before the block.

Packages (.asmpkg) #

Pre-compiled asmpython packages can be distributed as .asmpkg archives. They bundle object files, FFI declarations, and a manifest so users can pip install them and import normally.

shell
python -m asmpython pack mylib/ -o mylib.asmpkg
python -m asmpython install mylib.asmpkg

Windows target #

shell
python -m asmpython hello.py --target windows -o hello.exe
python -m asmpython hello.py --target windows --icon app.ico
python -m asmpython hello.py --target windows --icon icon.png

Produces a PE64 executable linked against msvcrt.dll. MinGW gcc is used as the linker. The --icon flag embeds an .ico or .png file as the executable's icon resource using windres. PNG files are auto-converted to ICO using Pillow if installed, or a minimal ICO wrapper (Vista+ compatible) otherwise.

Linux target #

shell
python -m asmpython hello.py --target linux -o hello

Produces an ELF64 binary linked against libc.so via system gcc.

Freestanding target #

shell
python -m asmpython kernel.py --target freestanding -o kernel.bin
qemu-system-x86_64 -kernel kernel.bin -serial stdio -display none

Produces a Multiboot1 kernel binary. Available APIs: print() (serial UART at 0x3F8), asmlib.hardware. No libc, no OS. Boots in QEMU directly.

Freestanding binaries have no memory allocator. String concatenation and collections are available only in stack-resident forms.

Freestanding 16-bit boot #

shell
python -m asmpython bootloader.py --target freestanding16 -o boot.img
qemu-system-x86_64 -drive format=raw,file=boot.img -serial stdio

Produces a raw 512-byte BIOS MBR + payload that transitions from real mode → protected mode → long mode, then jumps to the compiled Python entry point. No bootloader (GRUB, limine, etc.) needed — the output IS the bootloader.

Architecture #

text
source.py
   │
   ▼  Lexer      (asmpython/_compiler/lexer.py)
   │  tokens
   ▼  Parser     (asmpython/_compiler/parser.py)
   │  AST (ast_nodes.py)
   ▼  Sema       (asmpython/_compiler/sema.py)
   │  typed / resolved AST
   ▼  Codegen    (asmpython/_compiler/codegen.py)
   │  NASM asm text
   ▼  nasm → .obj / .o
   ▼  gcc  → .exe / ELF / .bin

The whole-program loader (program.py) walks the import graph, merges all project modules and bundled stdlib into a single compilation unit, then hands the merged AST to sema and codegen. This means:

  • No per-file object linking — everything ends up in one .asm
  • Cross-file inlining and dead-code elimination happen naturally
  • All top-level stdlib definitions become globally visible in the program

The register allocator uses a simple spill-to-stack strategy: each Python variable gets a dedicated stack slot; temporaries use a small set of scratch registers (r10, r11). Floats live in xmm0–xmm7. Function arguments follow the platform ABI (Microsoft x64 on Windows, System V on Linux).

Limitations #

  • No bignum — integers are 64-bit signed. Overflow wraps.
  • No GC — heap objects (lists, dicts, strings) are never freed. Long-running programs that allocate heavily will leak.
  • No dynamic dispatch beyond single inheritance — multiple inheritance, __mro__, metaclasses, and type() construction are not supported.
  • No generators / coroutines — yield, async/await, asyncio are not available.
  • No closures — inner functions can't capture variables from the enclosing scope. Use a class instead.
  • No eval / exec — dynamic code execution is not supported.
  • No reflection beyond isinstance/hasattr — runtime introspection is minimal.
  • Homogeneous collections — list / set elements must be a single type; mixed-type lists are rejected at compile time.
  • String keys only for dicts and sets.
  • Freestanding targets have no heap allocator — only stack-resident strings and structures are available.
  • No file I/O in freestanding — open() requires an OS.
