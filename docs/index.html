asmpython

Compile Python source to native x86-64 executables — no VM, no interpreter, no runtime dependencies.

platformWindows · Linux · Freestanding
python3.11+
licenseMIT

asmpython is a single-pass ahead-of-time compiler. It reads idiomatic Python, runs it through a lex → parse → sema → codegen pipeline, emits NASM assembly, and hands it to nasm and gcc to produce a standalone native binary with zero Python runtime overhead.

Supported output targets:

  • Windows (PE64) — .exe linked against msvcrt
  • Linux (ELF64) — ELF binary linked against libc
  • Freestanding (Multiboot1) — bare-metal kernel that boots in QEMU
  • Freestanding 16-bit — BIOS-bootable disk image (16-bit boot sector → 64-bit long mode)

Project status #

2.0.0-preview is the active development line. The headline work isn't a new language feature — it's a structural rewrite of the code generator around a proper SSA intermediate representation, which is the prerequisite for ARM64/macOS/Raspberry Pi targets, a real register allocator, and optimization passes that weren't previously possible against direct AST→NASM emission. The existing AST→NASM codegen.py path remains the one that actually ships builds today; the IR work is additive and lands incrementally behind its own pipeline.
2.0.0-preview IN PROGRESS
SSA IR (ir.py/ir_builder.py/ssa_build.py) + dead-code elimination pass; 27 new stdlib modules; Win64 ABI shadow-space fixes; @dataclass default-factory fix; NULL-truthiness fixes.
1.2.0 — Graphics everywhere
Lumen graphics/audio/input ecosystem: SDL2-backed lumen (Canvas, PixelBuffer, Image, Font, Joystick, Tilemap), bare-metal lumen.framebuffer, lumen.audio (SDL2_mixer).
1.1.0 — CPython parity expansion
Full operator-dunder dispatch, match/case, with statements, generators, closures, walrus operator, f-string format-spec mini-language, container repr.
1.0.x — Public launch
Core language, Windows/Linux/freestanding targets, first stdlib pass, asmlib hardware/network/gui bindings.

Confirmed work order toward 2.0.0

  1. Finish the SSA IR builder's mechanical AST-node coverage pass.
  2. Linear-scan register allocator.
  3. x86-64 IR lowering; validate full parity vs. the existing test suite.
  4. macOS Intel x86-64 target.
  5. ARM64 lowering (Linux first), then macOS Apple Silicon and Raspberry Pi.
  6. Raspberry Pi bare-metal (new freestanding ARM64 target).
  7. Garbage collector (refcounting).
  8. Optimization passes beyond dead-code elimination.
  9. Selfhost completion (asmpython compiling itself, end-to-end).
  10. Stdlib completion pass; release hardening (CONTRIBUTING/SECURITY/templates).
Full detail lives in docs/ROADMAP.md and CHANGELOG.md in the repository root.

Diagnostics

output
broken.py:3:5: semantic error: [E002] undefined function 'greet'
  greet("world")
  ^

All errors go to stderr with a non-zero exit code. By default every sema error in the file is collected and reported together (pass --one-error to stop at the first one; parse errors always stop early). Pattern matching #

Full PEP 634 match/case. Lowered to if/elif chains in sema — zero runtime overhead. match is a soft keyword.

python
# Literal, or-pattern, wildcard
match status:
    case 200: print("ok")
    case 404 | 410: print("not found")
    case _: print("other")

# Capture + guard
match cmd:
    case x if x.startswith("--"): print("flag", x)
    case s: print("cmd:", s)

# Sequence + starred
match lst:
    case []: print("empty")
    case [x]: print("one", x)
    case [first, *rest]: print("head", first, "tail", rest)

# Class pattern with __match_args__
class Point:
    __match_args__ = ("x", "y")
    def __init__(self, x: int, y: int): ...

match shape:
    case Point(x=0, y=0): print("origin")
    case Point(px, py): print("point", px, py)

# As-pattern
match val:
    case [x, y] as pair: print("pair", pair)

Supported: Literal, Capture, Wildcard (_), Or-pattern (|), Sequence ([p0, p1]), Starred (*rest), Class (Cls(kw=p)), As-pattern (p as name), Guards (if expr). Mapping patterns ({"key": v}) are not supported.

Functions #

python
def greet(name: str, times: int = 1) -> str:
    return (name + " ") * times

# *args variadic
def variadic(*args: str) -> None:
    for a in args: print(a)

# **kwargs
def kw_func(**kwargs) -> None:
    for k in kwargs: print(k, kwargs[k])

# First-class; closures; lambda
f: int = lambda x: x * 2
xs.sort(key=lambda x: x.lower())

# *expr unpack at call site (statically-known tuple)

my_func(*t)

# Decorators
@staticmethod
def util() -> int: ...

Default arguments: int, str, float, bool, None literals. Type annotations parsed and used for type inference (not enforced at runtime). Unannotated parameters infer type from call-site arguments. Closures capture free variables; nested functions can be passed and called.

Parameters inferred from call sites must agree across all call sites. Ambiguous cases default to int.

Generators #

Generator functions use yield inside while or for loops (including nested if branches). The generator transform rewrites the function into a state machine that resumes on next() calls.

python
def counter(n: int):
    i: int = 0
    while i < n:
        yield i
        i += 1

def evens(xs: list[int]):
    for x in xs:
        if x % 2 == 0:
            yield x

for i in counter(5): print(i)
g = counter(3)
print(next(g), next(g))

Generators are iterable via for and next(). StopIteration is raised when exhausted. Generator expressions (x for x in xs) are eagerly materialized into lists.

    def __init__(self, side: int) -> None:

Imports & modules #

python
import math
from os import getcwd, path
from . import utils           # relative
from .utils import helper

Two import modes:

  • Source stdlib — modules like re, json, collections, lumen are compiled whole-program alongside your code. All top-level definitions become globally visible.
  • FFI stdlib — math, os, sys, time, hardware, network use direct C runtime bindings.

User modules: import utils finds utils.py in the same directory and merges into the compilation unit. Whole-program compilation ensures zero linking overhead for user modules — the first definition of any name wins, so stdlib can be overridden by user code.

Inline assembly #

python
from asmpython.assembly import assembly_func

@assembly_func
def popcnt(x: int) -> int:
    """
    popcnt rax, rdi     ; SysV: x in rdi
    ret
    """

The docstring is raw NASM emitted verbatim as the function body. Arguments arrive in the platform's integer-argument registers (Win64: rcx/rdx/r8/r9; SysV/Linux: rdi/rsi/rdx/rcx/r8/r9).

Asm blocks inside a normal function

python
def rdtsc() -> int:
    asm {
        rdtsc
        shl rdx, 32
        or  rax, rdx
    }

Raw NASM inserted verbatim into the function body. The enclosing function's prologue/epilogue is still emitted; the asm block appears between them. Useful for instructions without Python-level wrappers, without giving up the rest of the function to hand-written assembly.

Inline FFI #

@extern declares a foreign function; the compiler emits an extern NASM directive and routes calls through the platform ABI. include() and link() add #include and -l flags to the compile step. This is compile-time/link-time binding — the symbol must be resolvable by the linker. For a library whose name isn't known until runtime, see import_binary.

Dynamic loading (import_binary) #

Loads a shared library at runtime (a real LoadLibraryW/dlopen handle), as opposed to @extern's compile-time/link-time binding. Functions are declared with @<handle>.imported and resolved via GetProcAddress/dlsym the first time they're called.

python
import sys
from asmpython import import_binary

if sys.platform == "win32":
    libc = import_binary("msvcrt.dll")
else:
    libc = import_binary("libc.so.6")

@libc.imported
def toupper(x: int) -> int: ...

print(libc.toupper(97))   # 65

Only scalar (int/float/str-as-pointer) parameters are supported — the foreign function's real signature isn't introspectable, so the stub's own annotations are the contract. Useful when the library to load isn't known until runtime (plugins, optional dependencies, platform-specific DLLs picked by name).

Windows (PE64) #

Default target when running on Windows. Produces a .exe linked against msvcrt.dll. Uses the Microsoft x64 ABI (rcx/rdx/r8/r9 with 32-byte shadow space). The entry point is main(int argc, char** argv).

shell
python -m asmpython prog.py               # auto-detects Windows
python -m asmpython prog.py --target windows -o prog.exe
python -m asmpython prog.py --icon app.png  # embed PNG icon

Networking (network/socket) auto-links -lws2_32; lumen auto-links -lSDL2 (and -lSDL2_mixer/-lSDL2_ttf as needed) only when actually used.

Every hand-rolled runtime helper and function prologue on this target reserves at least 32 bytes of shadow space below rsp before calling any external function, per the Win64 ABI — a 2.0.0-preview fix that closed several stack-corruption bugs in runtime helpers.

Linux (ELF64) #

ELF64 binary linked against glibc using the System V AMD64 ABI (rdi/rsi/rdx/rcx/r8/r9). Linked with -no-pie (the code uses absolute relocations, which modern gcc's default PIE mode would otherwise reject).

shell
python -m asmpython prog.py --target linux -o prog

Freestanding (Multiboot1) #

Bare-metal x86-64 kernel conforming to the Multiboot 1 specification. Boots under QEMU (-kernel), GRUB, and other Multiboot-compliant loaders. No OS; no libc.

  • VGA text-mode output + COM1 serial mirroring
  • Bump allocator (256 KB heap)
  • 64 KB stack
  • 32→64-bit long-mode setup with identity-mapped page tables (first 16 MB, 2 MB huge pages)
  • Unhandled exceptions show a flashing red screen and warm-reboot after 5 s

Use --onedir / --use-runtime-lib to keep the binary smaller. The runtime library bundles all helper code into libasmpython_rt.a.

Architecture & pipeline #

asmpython compiles through four sequential passes — the path every build actually takes today:

  1. Lex (lexer.py) — tokenizes source; handles all Python literal types, f-strings, indentation blocks
  2. Parse (parser.py) — recursive-descent parser builds an AST (ast_nodes.py); inlines closures via free-variable lifting; resolves generators into state machines
  3. Sema (sema.py) — type inference and semantic analysis; resolves method overloads, propagates element types, desugars match/case, with statements, properties, and comprehensions
  4. Codegen (codegen.py, ~14 000 lines, plus one subclass per target) — direct AST → NASM x86-64 emission; target-specific ABI handling

Whole-program compilation: all source files (including stdlib modules) are merged into a single compilation unit before sema. The first definition of any name wins, so stdlib can be overridden by user code.

Type system: structural, not nominal. Types flow from annotations and literals. Unannotated parameters are inferred from call sites. Class inheritance is tracked for virtual dispatch and isinstance.

Runtime: a set of hand-written _runtime_* helper functions (string ops, allocation, dict/list operations, exception propagation, dynamic dispatch) emitted as NASM alongside your compiled code. These can be inlined per-binary (--onefile, the default) or linked from a pre-built archive (--use-runtime-lib) for a much smaller .asm output.

SSA IR & optimization #

2.0.0-preview's structural change: a real SSA (static single assignment) intermediate representation between the AST and machine code, replacing direct AST→NASM emission for the parts of the compiler that have been migrated so far. This is what makes a real register allocator, target-independent optimization passes, and additional CPU architectures (ARM64) tractable — none of those are practical to retrofit onto per-target AST-walking codegen.

IR data model

ir.py defines a deliberately bare data model: Value (an SSA value with an id, a Kind — INT or FLOAT — and a back-pointer to its defining Instr), Instr (one operation: arithmetic, comparison, control flow, memory, or call), Block (a list of instructions plus predecessor blocks), and Function (a list of blocks). ir_builder.py wraps this in an ergonomic BlockBuilder — one method per op — that ssa_build.py (and tests) use to assemble IR by hand instead of constructing Instr nodes directly.

Design decisions

Two value kinds

Only Kind.INT and Kind.FLOAT exist at the IR level. ICMP/FCMP are value-producing (not branch-fused), which sidesteps the x86 ucomisd vs. ARM64 fcmp unordered-NaN comparison differences at the IR level rather than per-target.

RAW_ASM escape hatch

An Op.RAW_ASM instruction carries a {(OS, ABI): text} map so IR-lowered code can still call the ~75 hand-written _runtime_* helpers during migration, with a fixed argument convention (args[i] → the i-th of rax, rbx, rcx, rdx, …) instead of ABI-derived registers.

No internal jump labels in RAW_ASM

target_text can't mint fresh per-instance labels — two firings of the same call site would collide. Control-flow-heavy helpers are promoted to real typed IR blocks (PHI nodes, CONDBR) instead of being wrapped as a single RAW_ASM site.

Linear-scan register allocation (planned)

The IR's explicit def-use graph (via each Value.def_ back-pointer) is what a linear-scan allocator needs; this is plan-step 2, after the AST-node lowering coverage pass finishes.

Dead-code elimination

dce.py runs three passes over a Function's SSA form, iterating to a fixpoint:

  1. Unreachable block elimination — BFS from the entry block over the CFG; blocks never reached are dropped, and surviving blocks' predecessor lists and PHI incoming values are patched to match.
  2. Constant-branch folding — a CONDBR whose condition resolves to a compile-time CONST is rewritten to an unconditional BR to the taken arm; this routinely creates new unreachable blocks for pass 1 to clean up on the next iteration.
  3. Dead-instruction elimination — mark-and-sweep seeded from side-effecting instructions (STORE, CALL, RAW_ASM, BR, CONDBR, RET), propagated backward through the def-use graph; anything never reached — including PHI nodes — is dropped. LOAD is deliberately not seeded as a side effect: a load whose result is never read is dead.
python
from asmpython._compiler.dce import run_dce
run_dce(func)   # mutates func.blocks in place
All current SSA IR work is additive and gated behind its own pipeline — it does not change what python -m asmpython produces today. The migration path is: extend ssa_build.py's AST coverage → register allocator → swap in IR-based codegen for one target → validate output parity against the full test suite → repeat per target.

Limitations #

  • No bignum — integers are 64-bit signed; overflow wraps
  • Homogeneous lists — list[T] requires all elements to be the same type; list (bare) allows any
  • String keys only — dict and set elements must be strings (runtime limitation)
  • Single inheritance — multiple inheritance is not supported
  • No metaclasses — type() and __class__ are read-only
  • No dynamic attribute creation — all instance attributes must be assigned in __init__
  • No mapping patterns in match/case
  • Generator expressions are eager — (x for x in xs) materializes immediately
  • *expr unpacking at call sites requires a statically-known tuple (literal or named variable)
  • No async/await — asyncio ships as a subset of primitives, not a real event loop
  • No real TLS/SQLite — ssl and sqlite3 are API-shaped stubs pending a C library binding
  • No runtime introspection beyond isinstance, hasattr, getattr, type
  • No ARM64/macOS/Raspberry Pi targets yet — gated on the SSA IR migration; see SSA IR & optimization
Most limitations are by design to keep the compiler single-pass and the output zero-overhead. The subset covers a wide range of real programs — see examples/ in the repository for demonstrations.
