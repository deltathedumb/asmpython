asmpython is a single-pass ahead-of-time compiler. It reads idiomatic Python, runs it through a lex → parse → sema → codegen pipeline, and produces a standalone native binary with zero Python runtime overhead — either via a direct-to-object SSA IR backend or a NASM-text pipeline handed to nasm/gcc. See Backends: legacy & x86-64 for how the two relate.

Supported output targets:

  • Windows (PE64) — .exe, direct-to-object by default
  • Linux (ELF64) — ELF binary linked against libc
  • Freestanding (Multiboot1) — bare-metal kernel that boots in QEMU
  • Freestanding 16-bit — BIOS-bootable disk image (16-bit boot sector → 64-bit long mode)

The language itself is plain Python — see the CPython docs for syntax and stdlib semantics. These docs cover what's specific to asmpython: its public API, custom features, and current limitations.

Project status #

3.14-preview is the active development line (renamed from the earlier 2.0.0 working name to track CPython's own version number, so users don't need a lookup table). The headline structural change already landed: a direct-to-object SSA IR backend (--backend x86-64) is now the default backend for Windows/Linux builds, superseding the original NASM-text codegen.py pipeline (still available via --backend legacy for freestanding targets and anything not yet ported). See Backends: legacy & x86-64 for the full relationship between the two.
3.14-preview IN PROGRESS
x86-64 IR backend promoted to default; asmpython.mlang (embed and call into another language's source, compiled by a configurable external compiler); linear-scan register allocator hardening; whole-program reachability-walker fixes; a real bigobj-format COFF parser is the next known gap for the builtin linker.
1.2.0 — Graphics everywhere
Lumen graphics/audio/input ecosystem: SDL2-backed lumen (Canvas, PixelBuffer, Image, Font, Joystick, Tilemap), bare-metal lumen.framebuffer, lumen.audio (SDL2_mixer).
1.1.0 — CPython parity expansion
Full operator-dunder dispatch, match/case, with statements, generators, closures, walrus operator, f-string format-spec mini-language, container repr.
1.0.x — Public launch
Core language, Windows/Linux/freestanding targets, first stdlib pass, asmlib hardware/network/gui bindings.

Confirmed work order toward a real 3.14

  1. x86-64 IR backend lowering; validate parity vs. the full test suite. (in good shape — see internals page)
  2. macOS Intel x86-64 target.
  3. ARM64 lowering (Linux first), then macOS Apple Silicon and Raspberry Pi.
  4. Raspberry Pi bare-metal (new freestanding ARM64 target).
  5. Garbage collector (real refcounting — a prerequisite for full CPython C-extension support).
  6. Optimization passes.
  7. Selfhost completion (asmpython compiling itself, end-to-end).
  8. Stdlib completion pass; release hardening.
Full detail lives in RESUME.md, docs/ROADMAP.md, and CHANGELOG.md in the repository root.

Quick start #

python
# hello.py
print("Hello, world!")
for i in range(5):
    print(i)
shell
python -m asmpython hello.py      # produces hello.exe / hello (x86-64 backend, default)
./hello

Freestanding kernel

shell
python -m asmpython kernel.py --target freestanding -o kernel.bin
qemu-system-x86_64 -kernel kernel.bin -serial stdio -display none

Freestanding targets automatically use --backend legacy (the x86-64 IR backend doesn't support bare-metal output yet) — no flag needed.

Multi-target in one invocation

shell
python -m asmpython prog.py --target windows,linux

Lex/parse/sema run once; codegen and linking run once per target.

CLI reference #

shell
python -m asmpython <source.py> [options]

Input / output

OptionDescription
-o, --output <path>Output path (default: source stem + platform extension)

Target / backend / build mode

OptionDescription
--target <t>Comma-separated windows/linux/freestanding/freestanding16 (auto-detected from host if omitted)
--backend <name>x86-64 (default for windows/linux), legacy (default for freestanding targets, and the only one with @assembly_func support), ternary, or any backend registered via asmpython.backend.Backend(...)
--linker <name>gcc or builtin (the x86-64 backend's own from-scratch linker, its default unless a build needs gcc's own toolchain, e.g. asmpython.mlang) — or any linker registered via asmpython.linker.Linker(...)
--type executable|libraryProduce an executable (default) or a shared library (.dll/.so)
--emit-asmWrite .asm only — skip assemble/link (legacy backend only)
--checkFront-end only (lex/parse/sema), no codegen, no toolchain required
--one-errorStop at the first sema error instead of collecting all of them (parse errors always stop early)
--jsonWith --check, machine-readable JSON diagnostics array on stdout
--keepKeep the intermediate .obj/.o file after linking
--keep-assemblyKeep the intermediate .asm file after assembling (legacy backend only)
--icon <path>Embed .ico or .png as a Windows icon resource (Windows only; PNG auto-converted via Pillow or a fallback minimal ICO wrapper)
-of, --onefileSingle statically-linked binary (default)
-od, --onedirBundle directory: exe plus a resources//.resources/ folder holding the shared runtime library
--use-runtime-libLink the pre-built libasmpython_rt archive instead of inlining helpers (~50% smaller .asm output, legacy backend)
--no-pyinbin-fallbackDon't fall back to the pyinbin interpreter when native compilation rejects the source — report the native error directly instead

Toolchain overrides

OptionDescription
--nasm <path>Override nasm executable path (env: ASMPYTHON_NASM)
--gcc <path>Override gcc executable path (env: ASMPYTHON_GCC)

Information

OptionDescription
-h, --helpShow help and exit
-V, --versionShow version and exit
--explain <CODE>Describe an error code and exit (e.g. --explain E021, --explain L003, --explain P002)

Diagnostics

output
broken.py:3:5: semantic error: [E002] undefined function 'greet'
  greet("world")
  ^

All errors go to stderr with a non-zero exit code. By default every sema error in the file is collected and reported together (pass --one-error to stop at the first one; parse errors always stop early). Use --explain <CODE> for a full description of any error code, or --check --json for machine-readable output in editor integrations.
